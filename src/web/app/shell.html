Set it up oncea GitHub App is the whole of it — every token a box gets is minted from this one key
One credential, and skein derives the rest: a write token scoped to a box's own repository, and a read-only one covering everything you installed the App on — both minted per box, valid an hour, renewed while the box runs. Nothing below is needed on this path.

Reviews act as the skein App, but no App is set up — nothing will be posted, except in repositories where you stored a token.

Without a GitHub Appstore tokens yourself — this is the path that asks for more than one
For a fleet where installing an App is not an option. It costs what the App path avoids: one token per repository you want boxes to push to, kept in step by hand as they expire. Reads then come from public access, or from the read token under Your GitHub identity above.
Repository tokensone fine-grained PAT per repo, and one repo per PAT
Each covers exactly one repository, and that is the whole security argument: a token covering three would hand all three to whichever box receives it, because the helper that chooses between them runs inside the box as the agent's own uid. A helper routes; it cannot contain. A repo's token can also be set on its own card under Repositories.

The one credential that is not scoped to anything: whatever gh auth token returned, which is your whole GitHub account, sitting in the sandbox-wide secret and reachable by every box. Prefer it only for a fleet whose repos you would hand any box wholesale.

Seeding was two host-side halves — gh auth token read the host's login, sbx secret set -g wrote the host's keyring — and the machine-global store is deleted, because two fleets on one host shared one token through it. This switch now only says whether boxes are meant to push as the account; whether one actually can depends on a secret seeded before that deletion.

Apply ceilings to running boxesUnlike the next create's memory, a per-box ceiling is live — it changes on a running box straight away, with nothing to save or restart. Use this after editing the two fields above; no rebuild, no interruption to any box mid-turn.
Save every box's work to the hostCopies each box's whole tree out of the sandbox and onto the host — every checkout, everything uncommitted and unpushed, /tmp included — into a file that outlives the sandbox. Nothing is stopped and nothing is destroyed: boxes keep running and agents keep working through it. It takes about as much disk as the boxes are big, and minutes rather than seconds. When it finishes, this says where each box went and the line that puts it back.
Applying them is a job for the hostThese numbers are fixed when the sandbox is created, so applying them means destroying it and making it again — and skein is inside it. That is not something this page can offer you: the destroy would work, and there would be nothing left to bring the boxes back. Fleet lifecycle lives on the host.
